🔬 CRITICAL FINDING: TEST 4 ISSUE (NOW RESOLVED) 🔬
═══════════════════════════════════════════════════════════════════════════════

⚠️  ISSUE DISCOVERED:
    Cumulative sales calculations didn't match full sale calculations
    Cumulative FIFO: $4,500 vs Full FIFO: $7,000 ❌
    Cumulative LIFO: $9,000 vs Full LIFO: $7,500 ❌

🔍 ROOT CAUSE ANALYSIS:
    This was a TEST DESIGN ISSUE, not a code bug.
    
    The test calculated costs WITHOUT recording qtyOut entries in the ledger
    between calculations. In a real ERP:
    
    Real Flow:
      1. Calculate COGS for Sale 1 → $1,000 (FIFO)
      2. POST Sale 1 (record qtyOut in ledger) ← KEY STEP
      3. Calculate COGS for Sale 2 → sees updated inventory state
      4. POST Sale 2 (record qtyOut in ledger)
    
    Bad Test (what was happening):
      1. Calculate COGS for Sale 1 → $1,000
      2. Calculate COGS for Sale 2 → SAME inventory available!
      3. Calculate COGS for Sale 3 → STILL same inventory!

✅ RESOLUTION APPLIED:
    Updated Test 4 to record qtyOut entries between calculations.
    Now cumulative costs match FIFO/LIFO expected behavior:
    
    Sequential Sales (FIFO):
      Sale 1 (100u): $1,000   (100@$10)
      Sale 2 (200u): $3,000   (100@$10 + 100@$20)
      ─────────────────────
      Cumulative: $4,000 ✅
    
    Sequential Sales (LIFO):
      Sale 1 (100u): $2,000   (100@$20)
      Sale 2 (200u): $4,000   (200@$20)
      ─────────────────────
      Cumulative: $6,000 ✅
